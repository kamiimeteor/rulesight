# 报告页结构

第 2 版，2026-10-28 用真实会话看过后定稿。实现在 `report/`（React + shadcn/ui），以代码为准。

一次会话生成一页报告，是一个离线就能打开的 HTML 文件。从上到下：

## 1. 页头
- 会话名称（取任务描述）
- 开始时间、用时、总步数、对照了几条规则（规则文件名）
- 右上角：导出报告（独立 HTML 文件）

## 2. 三个汇总数字
- X 处违反（需要你处理），橙色
- Y 条遵守（每条都附了证据），蓝色
- Z 条不适用（这次没碰到相关情况），灰色
- 点数字切到下面对应的分页

## 3. 会话进度条
只讲一件事：当前选中的这条规则，证据在哪几步。
- 每一步一根细条，按顺序排开；子 agent 的步骤短一些
- 判定依据那一步：实色、最高，上方标"第 N 步 · 判定依据"
- 其他证据步骤：同色的浅色，加高
- 颜色跟着判定走：违反橙色，遵守蓝色
- 别处的违反只在上方留一个小三角 ▼，悬停显示是哪条，点击切过去
- 鼠标停在任一细条上，显示"第 N 步 · 类型：一句话说明"

## 4. 左侧：规则列表
- 顶部分页：违反 / 遵守 / 不适用，各带数量，默认打开违反
- 每条只占两行：第一行写发生了什么（不写步骤号，最多两行）；第二行写关键步骤号、步骤类型、规则在第几行
- 按关键步骤在会话里的先后排，和进度条从左到右一致
- 选中的那条：浅灰底，左边一道判定颜色的竖条

## 5. 右侧：选中规则的详情
- 判定标签和规则来源（例：CLAUDE.md 第 12 行）
- 标题、规则原文
- 发生了什么：一段话解释判定理由
- 证据：竖向时间线，按会话顺序；判定依据那一步直接展开原文，其他步骤点"看原文"展开
- 子 agent 的步骤缩进，挂在启动它的那一步下面；启动的那一步不是证据时也列出来，灰字，不能展开
- 建议怎么处理（只有违反才显示）：一句建议，加一条可以复制给 agent 的指令
- 这条判得对吗：判对了 / 判错了，存在浏览器里；可以导出复核结果（JSON），用于校准一致率

## 布局
- 页头、汇总、进度条在上；下面左右两栏一样高，正好占满一屏，各自滚动
- 左右比例约 5 : 7

## 视觉
- 组件用 shadcn/ui（zinc 灰），冷灰底色（#EEF0EE），白色卡片
- 违反用橙色（#C2410C），遵守用蓝色（#1D4ED8），不适用用灰色；三种颜色的明暗也不同，不只靠色相区分
- 中文字体 Noto Sans SC；命令、文件名、步骤号用 IBM Plex Mono。不联网加载字体，按本机已有字体依次回退
